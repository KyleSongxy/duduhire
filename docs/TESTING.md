# 自动化验证

本仓库分为 API 单元测试、真实 PostgreSQL 集成测试和浏览器端到端回归。端到端回归通过产品页面发起邮件验证、打开一次性链接、填写资料和提交咨询；它不读取浏览器 cookie、不使用预置登录状态，也不会连接用户正在使用的浏览器。

## 常用命令

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
```

Node.js 最低版本为 22.13。Linux CI 首次安装浏览器时使用 `npx playwright install --with-deps chromium`。`npm run check` 先执行 `check:repository`（核心文档本地链接、页面静态图片和字体路径），再执行 lint、前后端单元/接口测试和前后端构建；E2E 单独运行，因为它需要 PostgreSQL 与 Chromium。

## 手机号认证验证

单元测试覆盖 PNVS 响应合同、安全凭据加载、异常脱敏、隐藏输入与开关配置；使用合成凭据和替身客户端，不调用真实短信服务。

以下命令仅对显式指定的本机 `*_test` 数据库执行（先完成迁移），不读取个人数据库配置：

```sh
RUN_POSTGRES_TESTS=true \
TEST_PHONE_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/duduhire_test \
TEST_PHONE_ROUTES_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/duduhire_test \
npm run test:integration:phone
```

覆盖并发配额、浏览器绑定、验证码尝试次数、超时租约、注册初始身份保留、邮箱兼容、未知登录不建号、原子会话与重复消费。未提供相应变量会明确跳过，不可把跳过当通过。浏览器用例 `apps/web/e2e/phone-auth.spec.ts` 全部拦截 API，只验证界面状态与交互，不证明短信送达。真实 PNVS 联调必须另外获得号码与发送次数授权，并由收件人确认短信及亲自输入验证码；不得使用本地假码宣称注册已实测。

## Qwen 真实接口验证

先按部署指南在非同步的私有环境文件配置真实 Qwen 密钥、模型与匹配地域，不将密钥放入 Dropbox 仓库。运行以下命令会发送最多 4 次真实模型请求，可能产生费用；仅使用代码中固定的合成案例，不读取数据库或真实用户材料：

```sh
RUN_QWEN_SMOKE=true npm run test:qwen
```

检查两端事实提取、生成草稿、明确确认和修改后重新确认；确认与查看命令在本地流程引擎处理，不额外调用模型。未显式授权或缺密钥时直接退出，绝不改用离线回复。真实模型不稳定或未遵循字段契约时应按失败处理；结构检查通过也不等于平台核验或生产验收。

测试清单与测试代码的类型检查：

```sh
npm run test:e2e -- --list
npx tsc -p apps/web/e2e/tsconfig.json
```

## 数据库隔离

未设置 `E2E_DATABASE_URL` 时，启动器寻找本机 PostgreSQL 的 `initdb`、`pg_ctl` 和 `createdb`，在系统临时目录建立一次性私有数据库集群，数据库名为 `duduhire_e2e_test`，监听随机 loopback 端口。测试结束后停止该集群并清理本次临时目录，不触碰开发数据库。

可通过 `E2E_PG_BIN` 指定 PostgreSQL 二进制目录，例如：

```sh
E2E_PG_BIN=/opt/homebrew/opt/postgresql@17/bin npm run test:e2e
```

没有本机 PostgreSQL 二进制时，可以显式提供已创建的专用测试数据库：

```sh
E2E_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/duduhire_e2e_test npm run test:e2e
```

启动器只接受 loopback 地址、数据库名以 `_test` 结尾且不带 URL 查询参数的连接。它先应用仓库迁移，再创建随机 `e2e-…@example.test` 测试身份。显式提供的数据库不会被清空、删除或重置；测试写入的合成记录会保留。应为 E2E 分配独立数据库，不与集成测试并行共享表。运行账户需要迁移权限，不能使用生产数据库或开发数据副本。

## 启动方式与邮件验证

配置位于 `apps/web/playwright.config.ts`。启动器 `apps/web/e2e/support/start-stack.ts` 使用正式 `buildApp` 和 `PostgresRepository` 创建真实 API，启动 Vite 并将 `/api` 代理至该 API。默认测试页面为 `http://127.0.0.1:5179`；端口占用时使用 `E2E_WEB_PORT`，启动器不会接管已有服务。

唯一替换的外部边界是邮件发送器：测试通过现有 `EmailSender` 依赖注入捕获邮件，仅接受 `e2e-…@example.test` 地址，写入当前测试专用的受限临时目录。浏览器仍需经正常注册/登录接口、同浏览器绑定和一次性链接验证建立会话。生产应用中没有新增测试接口、管理员登录后门或验证码绕过。

管理员测试身份只在专用测试数据库中播种，UUID 通过本次 API 进程的 `ADMIN_USER_IDS` 白名单授权；该身份进入后台仍使用真实邮箱链接登录。AI 使用既有 `AI_MODE=local`，不调用付费 API。

若需手动观察隔离页面，可创建一个临时目录并将其绝对路径作为 `DUDUHIRE_E2E_STATE_DIR`，使用以下入口启动。此方式不会自动清理手动创建的目录；退出前按 Ctrl-C 停止服务，再清理该精确临时目录。

```sh
DUDUHIRE_E2E_STATE_DIR=/absolute/path/to/your/new-temp-directory \
E2E_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/duduhire_e2e_test \
E2E_WEB_PORT=5180 \
node --import tsx apps/web/e2e/support/start-stack.ts
```

`ready.json` 包含本次测试管理员邮箱和页面地址，`mailbox/` 包含捕获的合成验证邮件。这些临时文件应保持私有，不加入版本控制。

## 覆盖范围

| 回归路径 | 验证内容 |
| --- | --- |
| 邮箱注册与登录 | 发送反馈、发送中锁定输入、真实链接验证、跨浏览器拒绝、链接不可重用 |
| 需求方与专业人才 | 注册身份不可改、反向入口自动归位、个人资料刷新后保留、联系资料加密落库 |
| 问题梳理与身份卡 | 对话发送、数据库记录、刷新恢复、工作台完成状态 |
| 工作台失败恢复 | 接口故障显示错误而非“未配置”，重试恢复真实状态 |
| 导航与键盘 | FAQ/企业流程 tabs 的方向键/Home/End、375px 菜单焦点、背景隔离与 Escape 返回 |
| 定价咨询 | 三个 CTA 均提交真实 API，来源准确、密文落库、outbox 事件存在 |
| 附件 | 拒绝 PDF 等不支持的格式，文本摘录确实进入服务端记录 |
| 咨询后台 | 访客/普通用户拒绝、管理员列表不泄露联系方式、用途校验、审计查看、隐藏、状态更新与并发版本冲突 |

故障注入只在隔离浏览器测试上下文中临时拦截工作台请求，不修改生产 API 行为。测试使用单 worker，减少依赖外部限流窗口和共享通知数据的干扰；自动重试默认关闭，失败需要调查。

## 结果与边界

控制台报告执行数量与失败步骤；HTML 报告保存在 `playwright-report/`，失败截图和 trace 保存在 `test-results/`，均已忽略提交。可用 `npx playwright show-report` 查看报告。合成验证链接可能出现在失败 trace 的导航记录中，因此报告仍应限于测试团队。

本套件不会证明生产 SMTP 投递、Qwen 实际输出质量、DNS/TLS、生产最小权限、真实付款或通知 worker 的外部投递可用。SMTP/worker、数据库权限和部署健康检查需结合 API 集成测试、运维演练及部署前验证。不能把本地 E2E 通过描述为已经上线或全部外部服务就绪。

## 双身份回归要求

同一账户先以需求方保存需求，再切换为专业人才保存能力，切回后核对两类对话、草稿、匹配资料与工作台进度互不覆盖。检查刷新保留当前会话身份、基本资料共用、独立会话不被同步切换；访客显示两入口，登录后仅显示当前入口。同 Cookie 旧标签页请求与切换前迟到响应应触发 `ACTIVE_ROLE_CHANGED`，不能把旧内容写入或显示到新身份。另检查未登录切换拒绝、非法角色拒绝和管理员权限不随身份提升。以上是本版本回归要求，通过情况以本次测试输出记录为准。
