# 同一账户双身份升级验证

日期：2026-09-14。记录本地源码、临时 PostgreSQL、隔离浏览器的检查结果，不代表 kylesong.top 已部署。

## 改动范围

- 同一账户具备需求方与能力方身份。Header、手机菜单及工作台提供当前身份与切换按钮，成功后进入工作台。
- 需求方隐藏“完善能力档案”，能力方隐藏“梳理用人需求”；访客保留两个入口。
- 注册初始身份保存在 `users.role`，当前会话身份保存在 `sessions.active_role`。刷新保留当前身份；新建独立会话从注册初始身份开始。
- 基本资料共用；两类发现记录、确认结果与匹配发布分别保存。自身另一身份的资料不作为匹配候选人。
- 未发送文字、个人信息修改和匹配预览按用户、会话及身份恢复。发布同意不恢复；来源版本过期不能直接发布。浏览器 sessionStorage 不可用时不保证草稿恢复，附件需要重新添加。
- 同 Cookie 标签页同步身份；旧身份请求返回 `409 ACTIVE_ROLE_CHANGED`，迟到响应和旧组件异步操作不能混入新身份。
- 迁移 011 回填旧会话，兼容旧实例未显式写入 active_role 的会话插入；发行清单、授权、readiness 与核心文档同步更新。

新增 E2E 位于 `apps/web/e2e/dual-role.spec.ts`：

| 场景 | 核验 |
| --- | --- |
| 双身份保存与切回 | 同一用户、登录时间和期限不变；两边对话及未发送草稿独立保存 |
| 切换失败与过期请求 | 503 后身份保持且可重试；旧 client 请求不会写入 capability |
| 跨标签页 | 同一浏览器另一页同步当前身份 |
| 未保存个人信息 | 切回恢复修改；保存时不覆盖另一身份的新字段 |
| 未发布匹配预览 | 标题恢复，发布同意保持未勾选，无自动发布 |
| 手机入口 | 390px 菜单正确隐藏另一入口；320px 工作台可切换且无横向溢出 |

测试使用独立端口与临时数据库，邮箱为合成 `@example.test`，邮件由本地捕获器接收，发现回复使用本地流程引擎。它们验证交互与持久化，不验证真实模型质量、短信或邮件送达。

首轮测试修正了旧身份文案定位及自动跳转后的响应读取方式；修正后逐项通过。既有回归的首次页面加载超时与移动菜单焦点失败在单独复验时均未复现，未为此放宽断言或修改焦点逻辑。视觉检查发现的 921px Header 操作文字换行已通过调整登录态列宽和动作收缩修复，截图复核保持单行且无溢出。
