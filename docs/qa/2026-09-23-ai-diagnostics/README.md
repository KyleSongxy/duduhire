## 获授权发布后的长输入诊断

[三次候选探针摘要](native7-candidate-probes.json)使用同一份 3,125 字符、33 行的虚构履历；每次最多 1 个模型请求，均不访问业务 API、不写数据库、不使用真实用户资料。

1. native-7 原生 30 秒截止：30,009ms、未收到响应头，`qwen_timeout`。
2. 仅探针将等待延长到 90 秒：44,055ms 返回 HTTP 200，但严格业务校验报 `discovery_invalid_shape`；没有保存或输出原文，不能追溯具体违规字段。
3. 加入安全结构违规计数、仅探针等待 55 秒：40,428ms 返回 HTTP 200，违规代码为空，原文引用与来源校验通过，得到 `ready` 草稿。

后两项改变的是诊断 fetch 的信号，不是正式适配器上限，也不是 native-7 原生验收。它们证明该输入的完成时间可能超过原有 30 秒，但不能证明每次输出都有效。随后本地将 Qwen 默认与最大等待统一为 55 秒，保留当前 Nginx 60 秒、前端 120 秒预算，未放宽结构与证据校验；API 224 项测试、lint/build 通过。最终原生候选及上线结果另见部署记录。

native-8 在服务器通过候选启动与认证拒绝检查，但其[原生 55 秒探针](native8-candidate-probe.json)于 47,930ms 返回后被严格结构校验拒绝：4 个字段的引用数组超限，最多 6 条，而持久字段允许 4 条。另有 1 条引用不直接包含于输入，尚未进入逐句恢复校验，不能称全部引用有效。没有启用 native-8；仍运行 native-6。后续采用模型响应专用的有界引用整理，先验证所有引用、再按完整语境分组保留，任何无效引用仍拒绝，不通过截断丢弃错误条目。

native-9 候选启动和认证拒绝检查通过；[首次原生长探针](native9-candidate-probe.json)在 41,741ms 返回 HTTP 200，外层结构校验通过，最多 6 条原始引用、4 个字段超过首选数量，但正式流程仍以 `discovery_unsupported_evidence` 拒绝。1 条引用不直接包含于输入；现有计数不足以区分不精确引用和安全裁剪边界，因此不能直接断言为编造引用，也不能宣称长履历已经恢复。本次没有切换正式版本。后续诊断不得反复调用直至碰到成功；只能在固定次数内增加安全原因元数据，保留所有失败结果。

随后只进行一次[带分支原因的诊断](native9-evidence-diagnostic.json)：同一冻结正式模块、同一输入、原生 55 秒上限不变；本次 36,342ms、HTTP 200、正式结果 ready/缺失 0，原始及最终引用最多 4 条，内容全部来自保留原句。九类拒绝原因均为 0，纯内存影子回放与原函数等价。它证明该次流程可完成，但不能解释前一次失败或证明长期稳定。诊断工具的 35 项离线检查通过，服务器仅输出固定原因、数量与索引，不保存模型正文；正式包内容未改。此后完成 native-9 切换、公网 8/8 以及浏览器公开首页检查，未再调用模型，也未操作真实账号。
