# DuduHire 产品事实与范围

更新日期：2026-09-14（按源码核对；不代表本日生产验收）
适用范围：当前前后端项目

## 1. 产品定义

DuduHire 面向两类用户：有真实问题需要解决的需求方，以及希望用真实经历证明价值的专业人才。

```text
真实问题 → 目标与约束 → 相关能力 → 可信证据 → 合作确认 → 可验证结果
```

当前产品已建立邮箱或手机号独立账户、服务端会话、个人资料、服务端发现对话、明确发布后的双向匹配和企业联系申请基础；支持判断链前段持久化与相关资料比较，签约、项目交付和结算尚未完成。

## 2. 账户与当前使用身份

| 当前身份 | 入口 | 工作台主动作 |
|---|---|---|
| 需求方 `client` | `/talent` | 发起新需求 |
| 专业人才 `talent` | `/projects` | 完善能力身份卡 |

访客保留两种入口；登录后只展示当前身份的发现入口，另一入口通过身份切换进入。当前导航与页面标题继续使用“梳理用人需求”（`/talent`）和“完善能力档案”（`/projects`），保留现有页面设计。确认后在原入口内预览、明确发布，并查看本站用户主动展示的人才或需求项目，不另行改名为全站检索入口。

注册通过邮箱安全链接或手机号 PNVS 验证码确认所有权后才创建账户。手机号身份不生成虚构邮箱，也不自动合并邮箱账户。每个账户均有需求方与专业人才两种使用身份。注册选择保留为初始身份，当前会话身份可主动切换并在刷新后保持；基本资料共用，登录邮箱或手机号不能通过资料页修改。需求、能力档案、发现记录、匹配发布和工作台进度按账户与类型分别保存，切换不会复制或删除另一身份的内容。

“邮箱地址已验证”只在以下条件同时成立时显示：

- 一次性验证链接未过期且未被使用。
- 服务端在事务中成功消费 token。
- `users.email_verified_at` 已写入。
- 当前浏览器持有仍有效且未撤销的服务端会话。

## 3. 已实现

- 首页、工作方式、定价、企业服务、认证、工作台和 404 页面。
- 邮箱密码登录及经近期邮件验证授权的首次/重置密码；保存后退出全部会话并使旧邮件链接失效。登录页默认密码入口，仍保留邮件与短信方式；真实邮件依赖另行验收。
- 邮箱 Magic Link 注册与登录；可显式关闭邮件认证（`EMAIL_DELIVERY_MODE=disabled`）。
- 手机号 PNVS 注册与登录、浏览器绑定、发送限额与超时保护；默认关闭，启用后默认限指定号码，显式 `PHONE_AUTH_ALLOW_ALL_NUMBERS=true` 可开放大陆手机号。代码支持不等于真实短信送达验收。
- 规范化邮箱或手机号唯一登录身份、两种使用身份及对应联系方式所有权验证。
- HttpOnly Cookie、服务端会话读取、撤销和过期。
- PostgreSQL 个人资料读取与保存；邮箱和账户类型不可由资料接口修改。
- 个人资料未保存编辑可在当前浏览器会话内按身份恢复，仅缓存修改字段并与服务端最新其余字段合并；基本资料仍共用。匹配预览恢复文字及来源版本，不恢复发布同意，过期版本仍不能发布。存储不可用时当前编辑可用，但不承诺恢复。
- 个人资料版本冲突检测；可选联系方式加密后落库。
- 首页问题通过短期、浏览器绑定的 intake 在登录前后安全衔接。
- 认证/资料/发现/联系接口校验、限流、Origin 检查、迁移、测试与健康探针。
- 需求方问题发现与专业人才价值发现两条登录后流程。
- 服务端 Qwen 接口、分步追问、逐字段草稿与来源摘录、跳过/修改/确认、PostgreSQL 持久化和跨刷新恢复；保留显式 OpenAI 兼容模式，离线测试须显式选择本地演练。真实 Qwen 可用性仍取决于密钥、地域、模型权限和实际联调。
- 文字输入、文本附件有限摘录/元数据；语音输入依赖浏览器支持和麦克风授权。
- 工作台从服务端汇总邮箱或手机号验证与发现完成状态。
- 确认后的需求/能力可单独预览并明确同意发布；PostgreSQL 保存匹配快照及版本，支持更新、退出匹配和来源版本失效。
- 双向比较真实发布记录的受控工作标签、必要技能与合作/办公条件，返回相关理由及待确认事项；不使用模型生成的人物或项目，不把匹配当作录用决定。
- 私密示例匹配使用独立 `matching_examples` 表，不发布用户资料；所有示例标记 `isExample=true / contactable=false`，不混入真实结果。开发 seed 定义22条（11需求、11能力），实际数据库数量取决于导入批次。
- 企业联系表单加密入库并原子生成 outbox 事件。
- 默认关闭的咨询管理权限、跟进状态、带理由的联系方式访问审计，以及独立 SMTP 通知 worker；需配置管理员与收件邮箱后启用。
- 深浅色主题、移动导航和降低动态效果支持；不能据此声称已完成全面无障碍认证。
- 工作方式页品牌影片。

## 4. 有限实现

- AI 输出是建议和草稿；只有用户明确确认所见版本后才标记完成，修改后需重新确认。确认不等于平台验证，也不代替匹配资料的独立发布同意；尚没有完整模型评测与人工复核后台。
- 匹配仅限本站主动发布且来源版本仍有效的对端记录，使用 34 个受控工作标签及明确合作条件。最多在一批 500 份资料中比较、返回 20 条，达到上限时明确提示；不是自由文本人才搜索、全市场覆盖或能力质量排序。可对双方明确填写且同币种、同计价周期的预算，以及每周投入和开始日期排除冲突；不自动换汇，缺失值不视为满足条件。证据真实性不在自动判断范围。
- 发布字段必须由用户预览并同意展示给已登录用户；不自动公开个人资料、对话、附件、邮箱或联系方式。继续对话产生新版本后保守暂停旧发布，需要重新预览发布。退出匹配不等于删除所有历史数据。
- 文本附件仅支持 UTF-8 的 TXT、MD、CSV、JSON、HTML、XML；每份最多提取前 8,000 个字符，并提交元数据。不保存原文件，没有二进制文件服务、病毒扫描或材料核验。
- 收付款账户、项目、短名单、合作阶段和结果记录仍是界面路径说明。
- 企业联系申请提交成功只代表入库。后台通知有租约、重试与死信状态，但 SMTP 接受不等于团队已阅读；实际跟进需运营人员完成。当前不连接第三方 CRM。

## 6. 工作台前置条件

工作台展示三类前置条件：

1. 收付款账户：尚未接入，服务端状态固定为 `not_configured`。
2. 电话或邮箱（二选一）：以已完成的邮箱 Magic Link 或手机号 PNVS 验证作为真实完成依据。
3. 核心资料：需求方梳理用人需求，专业人才完善能力档案；完成状态来自 PostgreSQL 当前活跃草稿的 `flow.status=confirmed` 与确认时间，第一轮回答或未确认草稿不算完成。

个人资料已由服务端保存，当前使用身份通过专门的会话切换接口更新；基本资料共用。

## 7. 统一术语

| 术语 | 当前含义 |
|---|---|
| 真实问题 | 已发生或正在发生、会影响业务或工作的具体情境 |
| 问题简报 | 服务端保存的用人需求说明，包含待补充、待确认或用户确认状态；不是平台验证 |
| 能力档案 | 面向浏览和比较的专业能力资料总称 |
| 能力身份卡 | 基于经历、个人职责、行动和结果提炼的价值草稿；明确区分本人提供、AI 建议与用户确认 |
| 证据线索 | 可能支持能力或结果的材料；核验前不能称为平台验证 |
| 匹配理由 | 用户同意发布的需求与能力在受控工作标签、合作条件上的共同点及待确认差距；不是身份或专业能力验证 |
| 项目匹配 | 人才查看已发布的需求快照；不是已成立的合作、合同或项目管理记录 |
| 可验证结果 | 能回溯到合作目标的交付结果；当前未实现结果记录 |
| 手机号已验证 | 用户在绑定浏览器通过服务端 PNVS 验证后形成的账户事实 |
| 邮箱已验证 | 用户实际消费服务端一次性链接后形成的账户事实 |

## 8. AI 与信任边界

- 邮箱验证只证明当时能够访问该邮箱，不证明个人身份、组织授权或专业能力。
- AI 建议、用户自述、待确认资料和平台验证必须清晰区分。
- 信息不足时不能编造预算、结果、身份或证据。
- 上传材料只能形成待核对线索，不能自动升级为已验证事实。
- 系统不自动联系人才、签约、支付或替用户作最终雇佣决定。
- 匹配仅基于工作相关的确认标签与显式条件，不使用年龄、性别、邮箱、国籍等身份属性作排序，也不让模型生成候选身份或决定是否录用。
- 既有 UI、布局、字体和样式保持不变；阶段反馈与确认指令使用原对话、提示和能力卡区域。字段、完成标准和异常恢复见 [AI 交互流程](AI_FLOWS.md)。

## 9. 上线前需确认的产品问题

- 营销页仍包含深入证据核验、合作与结果管理的说明；当前标签/条件匹配不构成这些完整流程的实现。正式公开时需明确规划范围，不能将相关资料比较宣传成已核验能力或已完成合作。
- 定价页展示的套餐不构成可在线购买的订阅；联系表单只是业务咨询，当前没有订阅开通、账单和扣款服务。
- 仓库未提供隐私政策、服务条款、账户删除和数据导出入口。正式上线所需文本、处理责任人与流程尚待确定。
- 企业联系管理与通知需配置管理员账号、独立 worker、真实收件邮箱和跟进责任人，不能把未启用的部署配置当作已在运营。

## 10. 维护规则

- 只有可运行、经过验证且有服务端事实来源的行为才能写入“已实现”。
- 邮箱、角色、资料、路由、迁移或存储边界变化时，同步更新 README、架构和认证文档。
- 静态卡片、营销文案或前端缓存不能单独作为业务状态完成证据。
- 尚未后端化的能力必须继续标为演示或未来范围。
