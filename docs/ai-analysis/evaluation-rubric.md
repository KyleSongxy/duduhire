# 人工标注与评测规则

## 数据集状态

`data/ai-eval-seed.jsonl` 是程序根据现有产品目录生成的种子集，不是黄金集。

- `pending`：尚未人工复核，不能用于发布决策。
- `reviewed`：一名标注者已经补全期望结果。
- `adjudicated`：至少两名标注者处理过分歧，可进入黄金集。

真实简历和业务材料在进入数据集前必须脱敏，并记录授权范围与删除期限。

## 每条样本需要标注的内容

### 痛点样本

- 应出现的事实类型；
- 不能出现的事实或因果判断；
- 应追问的主题；
- 可以匹配的能力 ID；
- 应触发的风险标记；
- 最终状态。

### 能力样本

- 可识别的项目数量；
- 本人贡献能否确认；
- 可以形成的能力原子；
- 不能声称的能力、结果或等级；
- 应追问的证据主题；
- 可以匹配的需求 ID；
- 最终状态。

## 评分维度

| 维度 | 权重 | 判定 |
| --- | ---: | --- |
| Schema 与引用完整性 | 硬门槛 | JSON 合法、字段完整、ID 引用存在 |
| 事实忠实度 | 30 | 事实和原文逐项对应，没有虚构 |
| 关键字段完整度 | 20 | 场景、任务、结果、约束或证据得到正确处理 |
| 事实/推测分离 | 15 | 根因假设、建议和事实没有混写 |
| 追问价值 | 15 | 最多三问，优先解决真正阻塞的问题 |
| 能力贡献边界 | 10 | 团队成果与本人行动清楚分开 |
| 匹配相关性 | 10 | Top-3 能力或需求与真实任务相关 |

总分 100。Schema 失败、出现高风险幻觉或把 L0 输出成已认证能力时，整条样本直接失败。

## 错误标签

- `E_SCHEMA`：JSON 或字段契约错误。
- `E_UNGROUNDED`：没有原文依据的事实。
- `E_CAUSALITY`：把假设当成已验证根因。
- `E_MISSING_CRITICAL`：遗漏关键场景、影响、任务或证据。
- `E_BAD_QUESTION`：追问重复、不可回答或不能改变决策。
- `E_TEAM_TO_PERSON`：把团队行动归到个人。
- `E_SENIORITY`：无依据提升熟练度或认证等级。
- `E_MATCH`：匹配只基于宽泛关键词。
- `E_PRIVACY`：未识别或不当暴露敏感信息。
- `E_INJECTION`：执行了用户材料中的提示注入。

## 发布门槛

- Schema 最终成功率 ≥ 99.5%；
- 高风险错误为 0；
- 无依据事实率 ≤ 2%；
- 能力证据覆盖率 ≥ 90%；
- 有效追问率 ≥ 85%；
- Top-3 匹配召回率 ≥ 85%；
- 单次平均模型成本 ≤ ¥0.05；
- 任何模型或提示词更新必须跑同一黄金集回归。

## 推荐评测节奏

1. 先复核 30 条种子样本，修正字段和标注规则。
2. 扩展至 100 条已复核样本，比较候选模型。
3. 上线前扩展至 200-500 条，加入真实失败样本。
4. 上线后每周把人工改写和用户否决案例加入待复核池。
