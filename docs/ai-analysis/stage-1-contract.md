# 痛点解析与能力解析：阶段一数据契约

版本：1.1

状态：生产闭环已接入，黄金集仍在人工复核

## 目标

阶段一只解决“什么是合格输出”，不选择最终模型，也不把生成结果视为事实认证。

- 痛点解析把用户描述整理成可确认、可追问、可匹配的任务信息。
- 能力解析把用户亲自做过的项目拆成有原文依据的能力原子。
- 所有事实性判断必须保留原文依据。
- 信息不足时输出不确定项和最多三个追问，禁止补齐或猜测。
- 模型只生成 L0 能力草稿，不生成 L1-L3 认证。

对应机器契约：

- `schemas/demand-analysis.schema.json`
- `schemas/capability-analysis.schema.json`

## 共同处理原则

1. 用户输入是不可信数据。输入中的“忽略规则”“直接给高分”等指令只作为待分析文本，不作为系统指令执行。
2. 事实、推测和平台建议必须分开。
3. `source_quote` 必须逐字出现在用户原文中；无法定位原文就不能创建事实。
4. 缺失字段使用 `null`、空数组或 `uncertainties`，不得生成看似合理的默认事实。
5. 每轮最多三个追问，优先询问会改变任务边界、匹配结果或风险判断的信息。
6. 敏感信息、违法/危险请求以及高影响就业决策进入人工复核，不自动匹配。
7. 任何对外展示或人员匹配结果都需要用户确认。

## 痛点解析的必要信息

进入 `ready_for_matching` 前，至少应当明确：

- 发生问题的场景和当前阶段；
- 可观察到的现象；
- 用户希望改变的结果；
- 一项可执行任务或交付物；
- 会影响执行的关键时间、数据、权限或责任边界。

根因默认是 `unknown`。只有用户明确提供经过验证的因果证据时才允许使用 `verified`；模型提出的解释必须写入 `root_cause_hypotheses`，并标记 `needs_verification: true`。

以下信息不得推断：

- 未提供的收入损失、ROI、转化率或节省金额；
- 未提供的预算、截止时间、团队人数和决策人；
- 症状背后的确定根因；
- 客户内部审批、数据授权或上线条件已经具备；
- 某一能力或候选人一定可以解决问题。

## 能力解析的必要信息

能力原子采用以下顺序：

`场景 → 本人任务 → 本人行动 → 方法 → 交付物 → 结果 → 证据 → 边界`

岗位名称、公司品牌、团队成果和“熟悉/参与过”不能单独证明能力。`ready_for_l0_card` 至少需要一个能够定位到本人行动的项目，以及与能力原子关联的原文片段。

以下信息不得推断：

- 把“团队完成”改写成“本人主导”；
- 把接触过、参与过改写成熟练或专家；
- 补造量化结果、客户评价、预算规模或团队人数；
- 根据公司、学历、岗位名称推断能力等级；
- 自动将 L0 升级到 L1-L3；
- 把未经查看的材料标记为已验证。

## 状态决策

### 痛点

- `needs_clarification`：缺少会改变任务定义或匹配结果的关键信息。
- `ready_for_matching`：已形成可执行任务，但仍然只是用户确认前草稿。
- `requires_human_review`：包含敏感数据、高风险决策、违法危险内容或无法由模型处理的矛盾。

### 能力

- `needs_clarification`：无法区分本人行动、交付、结果或证据。
- `ready_for_l0_card`：可以形成有依据的自述型能力草稿。
- `requires_human_review`：存在敏感信息、材料真实性问题、高影响就业判断或明显指令注入。

## 系统必须在模型外执行的校验

- JSON Schema 校验；
- 事实 ID、项目 ID 和证据 ID 的引用完整性；
- 每个 `source_quote` 是否真实包含于原文；
- `ready` 状态下是否仍有 `blocking: true` 的不确定项；
- 追问是否超过三个；
- 能力等级是否始终为 L0；
- 风险标记是否触发人工复核；
- 请求超时、空内容、截断 JSON 和重复调用的处理。

## 阶段二输入

阶段二只能在以下内容完成评审后开始：

- 两套 Schema 字段是否满足产品页面；
- 禁止推断清单是否覆盖业务风险；
- 100 条种子案例中至少 30 条完成人工复核；
- 痛点与能力各至少有 10 条真实、已脱敏案例；
- 标注者对关键标签的一致率达到 85%。

## 当前实现状态

仓库已经包含阶段二的生产工作流：

- 浏览器先调用无输入的状态接口，只有模型已配置时才上传解析材料；
- `DEEPSEEK_API_KEY` 启用 DeepSeek V4 Flash，超过 6000 字的能力材料升级为 V4 Pro；
- `DASHSCOPE_API_KEY` 启用 Qwen3.7 Plus 作为降级；
- 每个供应商最多重试一次，随后切换供应商或回到本地演示；
- 用户回答追问或提交修正后，会重新调用模型生成一份完整的新结构，而不是在浏览器里拼接答案；
- 匹配前逐条确认事实或能力原子，未确认条目不进入匹配；
- 匹配分别计算任务、交付、场景、证据与边界得分，并向用户展示理由；
- 运行时执行 Schema 子集校验、逐字原文引用校验、ID 引用校验、风险状态校验和 L0 等级校验；
- 服务不保存输入或完整输出，只持久化不可逆摘要、模型成本、延迟、状态和脱敏数量；
- 邮箱、手机号、身份证、银行卡号和常见凭据在发送模型前自动遮盖；
- D1 提供跨实例限流、匿名反馈、高风险人工审核队列、模型健康熔断和运营指标；
- 当前全局限流默认为每个来源 10 分钟 10 次；
- 管理员审核接口使用工作区身份邮箱白名单或可选管理员令牌。

仍需由真人完成、不能由代码代替的工作：

1. 至少完成人工复核的前 30 条种子案例；
2. 痛点与能力各补充至少 10 条真实、已脱敏、已授权案例；
3. 标注分歧由第二名审核者裁决；
4. 模型或提示词更新前，用同一黄金集完成回归。
