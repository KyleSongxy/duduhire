## 2. 动效片要让观众理解什么

DuduHire 面向两个方向：有人需要把业务问题说清楚，也有人需要把实际经历整理成别人能理解的能力。AI 帮助整理，两端都需要看到依据、补充未知并核对自己的表述。

本片要传递的主句：

> 让需求说得清，让能力看得见。

观众看完应能回答三件事：

1. 我可以从一段问题或经历开始，不必先写一份完整资料。
2. 平台能把描述整理成有结构的需求说明或能力档案，并显示提炼依据。
3. 内容需要本人核对；资料之间的相关之处与待确认事项，帮助人作判断。

片中的运动承担解释任务：从原句中提取重点，表示信息整理；把原句与字段同时保留，表示可追溯；让两张资料并置，表示比较；改变确认状态，表示本人核对。空间中移动的对象必须能说清其业务含义。

## 4. DuduHire 的视觉方向

**明亮、克制、有工作材料和实体卡片质感的专业空间。** 白与近黑承担大面积，绿色负责动作、关联和状态；真实首页的自然工作影像负责人的温度。整个画面不套用参考片的蓝色科技滤镜。

| 设计项 | DuduHire 方向 |
|---|---|
| 品牌 | 使用现有黑色与浅绿色双 D 标识、DuduHire 字标 |
| 背景与表面 | `#f7f7f7`、`#fdfdfd`、`#eeeeea`；柔和自然光和轻微空间层次 |
| 文字 | 主文字 `#181818`，次文字 `#5e5e5e`，保持中文无衬线的清楚层级 |
| 品牌强调 | 主绿 `#0f8300`、浅绿 `#9fe870`、浅绿底 `#d8f7c7`；有意义的标签与连接才使用绿色 |
| 深色重点 | 能力卡采用 `#102a1d` 与 `#173728`，用作少量视觉重心 |
| 字体 | 沿用 `DuduHire Sans` 与现有中文后备字体栈；排版和缺字情况在渲染时核对 |
| 边缘与阴影 | 沿用 14/20 px 圆角体系的比例、细边与柔影；首页影像框保留大圆角气质 |
| 构图 | 一镜一个重点；完整网页交代位置，局部重排后的界面图层承担阅读 |
| 特征物 | 胶囊输入框、需求草稿、来源摘录、深绿能力身份卡、双 D 标识 |

能力身份卡是片中的记忆点：带挂绳与金属夹的工作证形态，落定后轻摆，随后展示本人职责和依据。它在当前产品中位于“查看能力身份卡”展开区域，不应伪装成首页常驻内容。状态使用真实的“AI 草稿”或“用户已确认”，保留本人确认与平台核验的区别。

参考片的蓝色霓虹描边、条纹光幕、太空、芯片、锁头、性能图表、全息手持画面，都替换成平台自己的界面与内容。最终画面不保留 SCP 品牌、英文套餐、技术图片墙或原片水印。

## 5. 全片分镜与屏幕文稿（已采用的 44 秒版本）

同一组“内部知识库”示例贯穿前后，降低理解成本。示例中的需求方与人才内容用于解释产品，持续标明为示例；不借此虚构平台用户、客户成果或成交记录。

| 时间 | 屏幕主句 | 内容与构图 | 动作及其含义 |
|---|---|---|---|
| 0–4 秒 | **让需求说得清** / **让能力看得见** | 白底双 D 标识与两行短句，接入真实首页的两种使用目的 | 首页从轻微透视落到可读位置；两种目的形成两端关系 |
| 4–10 秒 | **从一个问题开始** | 放大首页输入框：“客服资料太分散，想做能引用出处的知识库。”补充“6 周试点、远程合作；预算未定”。附近标“需求示例” | 光标完成少量输入并点击“开始梳理”；明确切入已登录流程，长文本按意群出现 |
| 10–16 秒 | **把需求整理清楚** | 原描述留在左侧；右侧三块依次出现：工作内容、预期目标、合作条件。预算保持“待补充/未确定”，标签以真实状态为准 | 从原句重点延伸到对应字段；模块展开后落定，表示整理而非自动补全未知事实 |
| 16–21 秒 | **从一段经历开始** | 切到“完善能力档案”。三行示例：“做过内部知识库。” / “我负责文档整理、检索与评测；” / “同事负责权限和上线。可提供脱敏报告。” | 与需求片段使用对应构图，说明两种入口遵循同样的整理方法；标“经历示例”。后续职责引文是本次输入中的连续原句节选，换行不改变原文 |
| 21–28 秒 | **让能力有据可循** | 打开“查看能力身份卡”，深绿卡片成为视觉重点；旁边展示“个人职责”“具体行动”“依据线索”，展开“查看提炼依据” | 能力卡在空间中轻摆后稳定；来源原句与对应字段同时高亮，说明表述有来源。报告显示为可提供的线索，不伪造已上传材料 |
| 28–34 秒 | **内容，由你确认** | 以能力档案演示修改和确认：从“知识库上线”修正为“完成检索与评测”，先显示“已修改 · 待确认”，再由用户确认保存。保留个人与团队角色的完整原句，以及“本人确认 · 未经平台验证” | 两次光标操作分别对应修改与确认，状态改变后停留。示范一次能力档案确认操作；需求方在下一镜以确认后的示例摘要呈现。确认不会自动把对话和联系方式公开 |
| 34–40 秒 | **看清工作与能力** | 并列展示已确认的需求示例与能力示例：需求工作、合作条件与人才个人职责、材料线索。两张资料均保留示例及本人确认标记；预算保持未定 | 对照知识库、资料整理、检索与评测的工作内容，帮助观看者理解双方表达。此镜为资料对照，不使用平台匹配结果、匹配分数或真实用户身份，也不声称已完成合作 |
| 40–44 秒 | **让需求说得清，让能力看得见。** | 双 D 标识与 DuduHire 字标收尾，辅以“梳理用人需求 / 完善能力档案”两个现有入口名称 | 两端资料收回品牌构图，最后至少 3 秒保持主要信息稳定，给观众完整记忆点 |

本轮已采用原提案允许的资料并列对照版本，主句确定为“看清工作与能力”。没有获得并用于本片的真实示例匹配输出，不制作虚构匹配结果。“主要工作”中的检索测试为 AI 建议，明确标“AI 建议 · 待确认”；预期结果和合作条件来自示例输入。来源标签、本人确认和未经平台验证的区别在画面中保留。

## 6. 运动与阅读规则

以下数值是为 DuduHire 提出的制作参数，并非对原片参数的测量结果。

- 网页入场约 0.7–1.0 秒；轻微透视后落到接近正面的阅读位置，偏转以约 4–8 度为起点调整。
- 信息重点展示时，镜头只保留极缓的推进。阅读阶段不同时转动网页、滚动内容和切换字幕。
- 同一镜头内先建立整体，再展开一个主要分组；字段间约 0.12–0.18 秒错开，随后留 2–3 秒稳定阅读。
- 多层布局最多同时强调 3 层；阴影、遮挡与前后位移保持一致，避免每张卡片独立漂浮。
- 挂绳能力卡只在进入时有一次有重量的摆动，摆幅约 2–4 度后衰减。与字幕阅读并行时应基本稳定。
- 来源高亮、修改和状态改变使用同一套绿色反馈。连线只连接实际相关字段，不连到人物身份或虚构评分。
- 主句建议 8–14 个中文字符；重点内容在 1080p 画布中约 40–48 px，主句约 72–88 px，示例与状态标签保持可读。最终以 960×540 播放尺寸检查。
- 一段镜头以一个主要运动为核心。转场结束后才能展开新内容；光标只演示必要的输入、修改和确认。
- 入场和出场分别设计，跨镜头保持运动方向与空间关系。以时间轴检查先后顺序，不机械复用同一转场。

## 7. 本地制作路线

核心采用 **Blender + FFmpeg**：依据网站现有素材、字体和组件关系重新排版清晰的界面图层；在 Blender 中设置平面、相机、软光、阴影、深度与能力卡摆动，再输出图像序列，用 FFmpeg 合成为 MP4。

网页图层有两种清晰的素材类别：实际页面截图用于交代产品位置；为镜头阅读重新编排的界面图层用于展示重点。后者需要标明为产品交互演示，不当作真实服务操作录屏。网站文字与 Logo 使用现有资产和确定的排版，中文文字不交给图像生成模型重画。

本地 Blender 已输出 1320 帧，经 FFmpeg 合成为 44 秒独立预览。最终文件的规格、完整解码、时间顺序抽样与 QuickTime 正常速度播放检查已完成，证据见 [交付说明](README.md)。本轮没有运行新的真实 AI 会话或平台服务验收。浏览器连接此前超时，本片采用既有首页截图交代位置，其余为依据当前代码和示例文案重建的产品交互演示图层。

本片独立使用 `tools/duduhire-product-motion/` 目录，制作独立预览及其源文件；既有人物片与网站视频的文件、引用保持原有状态。本地素材与静帧检查通过不等于完整成片已验收。

## 8. 完成标准

1. 品牌、色彩、字体、界面对象和叙事都能对应 DuduHire；成片不残留原片内容。
2. 每个主要动作都能解释其信息含义，来源、字段、确认状态前后对应。
3. 需求与能力两端都能看懂；示例与真实状态明确，未知条件不会被动画自动填成事实。
4. 中文在常见嵌入播放尺寸下清楚，重点有稳定阅读时间，遮挡、运动模糊和倾斜不会破坏理解。
5. 最终 MP4 完成分辨率、帧率、时长、解码与音轨检查，并检查正常速度播放的镜头衔接、文本、片尾；源素材抽帧通过不能替代成片验收。
