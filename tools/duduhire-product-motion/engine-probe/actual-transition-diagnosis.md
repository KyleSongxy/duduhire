## 独立发现：透明度被整数化

`value_key` 将 `0` / `1` 整数直接赋给自定义 `opacity`，旧工程透明度曲线按整数值工作，导致本应连续的淡入淡出变为 0/1 跳变。

建议在根脚本中统一使用浮点值，并重新构建工程：

```python
obj[prop] = float(value)
obj.keyframe_insert(data_path='["' + prop + '"]', frame=frame(t))
```

仅把旧对象属性改为浮点并调用 `update_autoflags`，此次实验仍保留了旧整数曲线行为；探针通过在副本中重建相同关键点的浮点曲线验证：

| 帧 | 对象 | 原值 | 浮点曲线 |
| --- | --- | ---: | ---: |
| 0124 | 首页 | 1 | 0.951407 |
| 0124 | 需求输入 | 1 | 0.634861 |
| 0481 | 原始需求 | 1 | 0.961734 |
| 0481 | 经历输入 | 0 | 0.339525 |
| 0628 | 能力卡 | 0 | 0.205584 |
| 0839 | 能力卡 | 1 | 0.794416 |

`backfaces-float` 的四张验证图均无撕裂。连续透明度恢复后，原有时间轴交叉淡化会自然显示前后内容重影；这属于转场构图与阅读节奏，仍需根任务检查，而不是本次透明排序缺块。
